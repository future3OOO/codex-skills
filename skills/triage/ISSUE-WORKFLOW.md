# Issue Workflow

Stay within explicitly authorized issue actions; do not re-ask authorization.
Every posted issue or comment starts with:

```
> *This was generated by AI during triage.*
```

## Roles and transitions

Each triaged issue has one category: `bug` (broken behavior) or `enhancement`
(new feature/improvement), and one state:

- `needs-triage`: maintainer evaluation.
- `needs-info`: waiting on reporter.
- `ready-for-agent`: fully specified for an AFK agent.
- `ready-for-human`: requires human implementation.
- `wontfix`: will not be actioned.

Use the maintainer's label mapping for these canonical roles; ask if absent
before changing labels. Reconcile conflicts to the
maintainer's explicit target; ask only if unknown. Normally unlabeled moves to
`needs-triage`, then another state; reporter replies return `needs-info` to
`needs-triage`. Honor explicit overrides; ask before unauthorized unusual transitions.

An explicit label-only override (e.g. "move #42 to ready-for-agent") performs
only the requested label action: no automatic brief, extra comment, or grilling.
Writing/revising a brief still requires the [authoring gate](SKILL.md#author-a-brief).

## Attention and context

For "what needs attention", query three buckets, oldest first: unlabeled;
`needs-triage`; and `needs-info` with reporter activity since the last triage notes.
Show counts and one-line summaries; let the maintainer pick.

For a specific issue:

1. Read body, comments, labels, reporter, and dates. Resume from prior triage
   notes and reporter answers; never re-ask resolved questions. For an explicitly
   requested PR, inspect its diff and verify claimed behavior. Explore the code
   using its domain glossary and ADRs. Read `.out-of-scope/*.md` and surface
   similar prior rejections per [OUT-OF-SCOPE.md](OUT-OF-SCOPE.md).
2. Recommend category/state with decisive evidence. Apply an already authorized
   update; otherwise wait for direction.
3. For bugs, attempt reproduction before grilling: trace the reported steps and
   code path using real probes. When authoring a brief, obey the investigation
   limits in SKILL.md. Report confirmed repro, failed repro, or insufficient
   detail (a `needs-info` signal).
4. Clarify with `/grill-with-docs` if needed. Author briefs through the gate
   above and [AGENT-BRIEF.md](AGENT-BRIEF.md), the single contract.

## Outcomes

- `ready-for-agent`: reconcile one authoritative `## Agent Brief`, never append
  a competing version; retain category/state and the disclaimer on the issue.
- `ready-for-human`: same contract, with the human dependency (judgment, access,
  design decision, or manual testing).
- `needs-info`: post `## Triage Notes` with **What we've established so far** and
  **What we still need from you (@reporter)**. Preserve resolved findings and ask
  specific actionable questions, not generic requests for more information.
- `wontfix` bug: explain politely and close when authorized.
- `wontfix` enhancement: follow OUT-OF-SCOPE.md to record the rejection and close.
  Verified implemented behavior is not a rejection: point to its implementation,
  without adding an out-of-scope entry or automatically labelling it `wontfix`.
- `needs-triage`: apply the role; comment only if authorized and useful.

Handovers need only the issue link and applicable workflow/worktree pointer,
unless a task-specific exception is necessary.
